## 2. ติดตั้งของที่ต้องใช้

```bash
cd 511salon
python3 -m venv .venv
source .venv/bin/activate
pip install pillow pillow-heif
```

ต้องใช้ venv เพราะ macOS รุ่นใหม่บล็อก `pip install` ลงเครื่องตรง ๆ (`externally-managed-environment`)
**`pillow-heif` ขาดไม่ได้** รูปเป็น `.heic` จาก iPhone ซึ่ง Pillow เปล่า ๆ อ่านไม่ออก
ทุกคำสั่ง `python3` หลังจากนี้ต้องรันใน venv ที่ activate แล้ว

> `tools/process-photos.py` ยังไม่ได้ import `pillow_heif` เพราะบนคลาวด์ไม่มีรูป `.heic` ให้ทดสอบ
> **ให้เพิ่มบรรทัดนี้เข้าไปในสคริปต์ก่อนใช้งาน** ต่อจากบล็อก `from PIL import ...`:
> ```python
> try:
>     import pillow_heif
>     pillow_heif.register_heif_opener()
> except ImportError:
>     pass   # ไม่มี pillow-heif ก็ยังใช้กับ jpg/png ได้
> ```
> แล้วทดสอบว่าอ่าน `.heic` ได้จริงก่อนไปต่อ

## 6. ตรวจการครอบตัดทุกช่อง

**เปิดดูไฟล์ผลลัพธ์จริง อย่าเชื่อว่าสคริปต์ครอบถูก** โดยเฉพาะรูปที่มีคน — หัวขาด ตัวแบบชิดขอบ
หรือตัดจนไม่เห็นทรงผมคือใช้ไม่ได้ เพราะทรงผมคือสิ่งที่ต้องขาย

ครอบไม่สวยให้แก้จุดโฟกัสใน `511salon/assets/img/_originals/focus.json` แล้วรันช่องนั้นซ้ำ:

```json
{ "rail-keratin": [50, 25], "work-05": [40, 55, 1.3] }
```

`[x%, y%]` คือจุดที่อยากให้อยู่กลางกรอบ · ตัวที่สาม `zoom` (>1) ทำให้กรอบเล็กลง เลื่อนได้ทั้งสองแกน

## 7. แก้คำบรรยายให้ตรงกับภาพ

ทุกช่องมี `alt` และบางช่องมี `<figcaption>` ที่เขียนไว้ล่วงหน้าตอนยังเป็นภาพชั่วคราว
**ต้องแก้ให้ตรงกับสิ่งที่อยู่ในภาพจริง** — คำบรรยายตามภาพ ไม่ใช่ให้ภาพตามคำบรรยาย

- `alt` เขียนเป็นภาษาไทยที่บรรยายภาพจริง ไม่ใช่ที่ยัดคีย์เวิร์ด (ใช้ทั้งกับโปรแกรมอ่านหน้าจอและ Google Images)
- **ห้ามเดาชื่อบริการเอง** ถ้าดูรูปแล้วไม่แน่ใจว่าเป็น "ยืดเคราติน" หรือ "ยืดวอลลุ่ม" ให้ถามผู้ใช้
  ชื่อบริการผิดบนเว็บร้าน = ลูกค้าจองผิดความคาดหวัง
- ตอนนี้ `work-01` ถึง `work-04` มีคำบรรยายที่เขียนจากการดูภาพแล้ว แต่ยังไม่มีใครยืนยัน
  ให้เอาไปถามผู้ใช้พร้อมกันในข้อ 8

## 9. ตรวจก่อน commit

ยังไม่มีชุดทดสอบอัตโนมัติ **ต้องเปิดเบราว์เซอร์จริงตรวจเองที่ 1440px และ 390px** อย่างน้อย:

- ไม่มี console error และไม่มี request ที่ 404

## ข้อห้าม — อ่านก่อนแก้ CSS หรือ HTML

รายละเอียดเต็มอยู่ใน `511salon/CLAUDE.md` สรุปที่พังง่ายที่สุด:

- **`line-height` พาดหัวคือ 1.25 ห้ามลดต่ำกว่า 1.22** ภาษาไทยวางสระบนซ้อนวรรณยุกต์ได้สองชั้น
  ต่ำกว่านี้บรรทัดชนกันจริง (เจอตอนทดสอบ ไม่ใช่ทฤษฎี)
- **`picture{display:contents}` ห้ามลบ** `.hero-img` วางแบบ absolute และบล็อกที่ตั้งร้านนับ `img`
  เป็นลูกของ grid ถ้า `<picture>` กลายเป็นกล่องเลย์เอาต์จะเพี้ยนทั้งคู่
- **hero ห้ามเอาตัวอักษรไปทับภาพ** ภาพของร้านเป็นแนวตั้ง 9:16 ทั้งหมด ถ้าทำเป็นภาพเต็มจอแล้วพิมพ์ทับ
  พาดหัวจะพาดกลางใบหน้าพอดี ตอนนี้จึงเป็นภาพอยู่บน/ตัวอักษรอยู่ล่าง (มือถือ)
  และภาพครึ่งขวา/ตัวอักษรครึ่งซ้าย (เดสก์ท็อป) ขอบภาพไล่จางด้วย `mask-image`
- **`<meta name="robots" content="noindex,nofollow">` ห้ามลบตอนนี้** กันไม่ให้ Google เก็บหน้าพรีวิว
  บน github.io ไปแข่งกับโดเมนจริง จะลบตอนขึ้น `511salon.com` เท่านั้น
- **ห้ามใส่ `AggregateRating` ใน JSON-LD** Google ไม่นับรีวิวที่เจ้าของเว็บใส่เอง และเสี่ยงโดน manual action
- **ห้ามสร้างหน้าแยกรายพื้นที่** (บางปู ตำหรุ สำโรง) ร้านมีสาขาเดียวคือ BTS เคหะฯ
  หน้าที่ยิงคีย์เวิร์ดพื้นที่ที่ไม่มีร้านตั้งอยู่จริงคือ doorway page ซึ่ง Google ลงโทษ
  พื้นที่พวกนี้อยู่ใน `areaServed` ของ JSON-LD และพูดถึงในเนื้อหาแทน
