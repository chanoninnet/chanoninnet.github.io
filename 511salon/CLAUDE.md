# 511 SALON — บันทึกส่งต่อ

เว็บไซต์ร้านทำผม 511 SALON (สมุทรปราการ) หน้าเดียวจบ แนะนำร้านและโชว์ผลงาน
HTML + CSS + JavaScript ล้วน **ไม่มี build step ไม่มี dependency** ทุก path เป็น relative
จึงย้ายจาก `chanoninnet.github.io/511salon/` ไปเป็นรากของ `511salon.com` ได้โดยไม่ต้องแก้อะไร

เอกสารอ้างอิง — อ่านก่อนแก้ของที่เกี่ยวข้อง:

| ไฟล์ | เนื้อหา |
|---|---|
| [`../design/511-salon-blueprint.html`](../design/511-salon-blueprint.html) | แบบเต็ม: ทิศทางการออกแบบ ดีไซน์ซิสเทม โครงสร้าง URL แผน SEO ทั้ง 7 ชั้น แผนงานเป็นเฟส |
| [`PHOTOS.md`](PHOTOS.md) | ช่องภาพทั้ง 25 ช่อง ต้องถ่ายอะไร กติกาการถ่าย และวิธีรันสคริปต์ |
| [`README.md`](README.md) | โครงไฟล์ เช็กลิสต์ก่อนขึ้นโดเมนจริง และเหตุผลของการตัดสินใจหลัก |

## เริ่มงานบนเครื่อง

```bash
git fetch origin && git checkout claude/511-salon-website-seo-xkxe3g
pip3 install pillow          # ใช้เฉพาะตอนแปลงภาพ
cd 511salon && python3 -m http.server 8765     # เปิด http://localhost:8765/
```

เปิดไฟล์ `index.html` ตรง ๆ ด้วย `file://` ไม่ได้ — ฟอนต์กับ ES module จะโดน CORS บล็อก

## สถานะตอนนี้

- **ทำแล้ว** หน้า landing ครบ 11 บท · ดีไซน์ซิสเทม · SEO เทคนิคพื้นฐาน (title/description/canonical/OG/JSON-LD) · ท่อประมวลผลภาพ
- **ภาพจริง 6 ช่องจาก 25** — `hero`, `hero-portrait`, `work-01` ถึง `work-04` ที่เหลือยังเป็นภาพชั่วคราวที่เขียนบอกไว้ในภาพว่าต้องใส่อะไร
- **ยังไม่ได้ทำ** หน้าบริการรายตัว 6 หน้า · หน้าราคา · หน้าที่ตั้งร้าน · FAQ · บล็อก · เวอร์ชันภาษาอังกฤษ (เฟส 2–4 ใน blueprint)

## สิ่งที่ต้องรู้ก่อนแก้

**หน้านี้ใส่ `noindex` ไว้** กันไม่ให้ Google เก็บหน้าพรีวิวบน github.io ไปแข่งกับโดเมนจริง
การลบบรรทัดนี้เป็นข้อแรกของเช็กลิสต์ก่อนขึ้นโดเมนจริงใน README

**ข้อมูลร้านหลายจุดยังไม่ยืนยัน** ค้นด้วย `grep -n "TODO" index.html` — ที่อยู่เต็ม พิกัด GPS
ลิงก์ LINE ตัวจริง ลิงก์ Google Maps เวลาปิดร้าน ทุกจุดนี้ไปโผล่ทั้งใน JSON-LD และในหน้า

**ร้านมีสาขาเดียว** คือ BTS เคหะฯ — สาขาบางปูถูกถอดออกทั้งหมดแล้ว ส่วน `areaServed`
ยังมีบางปู/ตำหรุ/สำโรง อยู่ เพราะเป็นพื้นที่ที่ลูกค้าเดินทางมาจาก **ห้ามสร้างหน้าแยกรายพื้นที่**
ที่ไม่มีร้านตั้งอยู่จริง Google เรียกว่า doorway page และลงโทษ

**`line-height` ของพาดหัวคือ 1.25 ห้ามลดต่ำกว่า 1.22** ภาษาไทยวางสระบนซ้อนวรรณยุกต์ได้สองชั้น
ค่าที่ต่ำกว่านี้ทำให้บรรทัดชนกันจริง (เจอตอนทดสอบ ไม่ใช่ทฤษฎี)

**ไม่มี `AggregateRating` ใน JSON-LD โดยตั้งใจ** Google ไม่นับรีวิวที่เจ้าของเว็บใส่เอง
และเสี่ยงโดน manual action ให้เก็บรีวิวไว้ที่ Google Business Profile

**`picture{display:contents}`** จำเป็น ไม่ใช่ของประดับ — `.hero-img` วางแบบ absolute
และบล็อกที่ตั้งร้านนับ `img` เป็นลูกของ grid ถ้า `<picture>` กลายเป็นกล่องเลย์เอาต์จะเพี้ยนทั้งคู่

**hero ไม่วางตัวอักษรทับภาพ** ภาพของร้านเป็นแนวตั้ง 9:16 ทั้งหมด (ถ่ายจากมือถือ)
ถ้าเอามาทำภาพเต็มจอแล้วพิมพ์ทับ พาดหัวจะพาดกลางใบหน้าพอดี — มือถือจึงวางภาพไว้บน
ตัวอักษรอยู่ล่าง เดสก์ท็อปวางภาพไว้ครึ่งขวา ตัวอักษรครึ่งซ้าย ขอบภาพไล่จางด้วย `mask-image`

## ใส่ภาพจริง

```bash
python3 tools/process-photos.py --list                    # ช่องไหนยังขาด
python3 tools/process-photos.py --from ~/MyProjects/hair-photo --list
python3 tools/process-photos.py --from ~/MyProjects/hair-photo \
    hero=IMG_1234.jpg work-05=IMG_1240.jpg                # จับไฟล์เข้าช่องเอง
python3 tools/process-photos.py                           # ทุกช่องที่ตั้งชื่อตรงกับช่อง
```

สคริปต์ครอบตัดตามสัดส่วนของแต่ละช่อง ย่อเป็น 480/960/1600 แปลงเป็น AVIF + WebP + JPG
แล้วเปลี่ยน `<img>` เป็น `<picture>` พร้อม `srcset` ให้เอง รวมถึง `preload` ของ hero และ `og:image`
ครอบตัดไม่สวยให้แก้จุดโฟกัสใน `assets/img/_originals/focus.json` — `[x%, y%]` หรือ `[x%, y%, zoom]`

**เคสเทียบก่อน–หลังต้องครบทั้ง 6 ช่องพร้อมกัน** ไม่งั้นสคริปต์จะไม่แก้ HTML ส่วนนั้น
เพราะการสลับเคสทำโดยแทนชื่อช่องใน `src`/`srcset` ถ้าแปลงแค่บางคู่จะเจอภาพเสีย

**แคปชันต้องตามภาพ ไม่ใช่ให้ภาพตามแคปชัน** ชื่อบริการผิดบนเว็บร้าน = ลูกค้าจองผิดความคาดหวัง
และภาพลูกค้าทุกภาพต้องได้รับความยินยอมก่อน (เชิงอรรถข้อ 3 ท้ายหน้าประกาศไว้แล้ว)

## ตรวจก่อน commit

ยังไม่มีชุดทดสอบอัตโนมัติ ตรวจด้วยเบราว์เซอร์จริงที่ **1440px และ 390px** อย่างน้อย:

- ไม่มี console error และไม่มี request ที่ 404
- ไม่มีการเลื่อนออกด้านข้าง (`documentElement.scrollWidth === clientWidth`)
- `document.head.children.length` ยังเป็น 25–26 ไม่ใช่ 3
  (เคยพลาดมาแล้ว: แทรกคอมเมนต์ซ้อนในคอมเมนต์ ทำให้ `<head>` ปิดก่อนกำหนดแล้ว
  เนื้อหาทั้งหมดไหลลงไปอยู่ใน `<body>` — หน้าตายังดูปกติ แต่เลย์เอาต์เพี้ยนบนมือถือ)
- ปุ่มเลื่อนการ์ดผลงาน · ตัวกรองแกลเลอรี · แท็บสลับเคสก่อน–หลัง · เมนูมือถือ ยังทำงาน
- ปุ่ม LINE ยังอยู่เหนือขอบจอบน iPhone SE (375×667)
